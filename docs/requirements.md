# 需求规格说明书

## 目标和边界

在少量宿舍楼内完成从提交问题到验收的报修流程，并为每次处理提供可追溯记录。适用角色为学生、维修人员和管理员。业务以提交、派单、维修、验收与反馈为主线，支持电脑和手机操作。

## 功能需求

| 编号 | 需求及验收标准 |
|---|---|
| AUTH-01 | 三类用户可注册与登录；非学生注册必须校验邀请码；重复用户名返回409 |
| AUTH-02 | 密码不少于10位且含字母和数字，最多64字符且UTF-8不超72字节；bcrypt盐化哈希保存 |
| AUTH-03 | 修改密码需原密码；修改后所有已登录会话失效 |
| AUTH-04 | 每个IP及用户名在5分钟内失败10次后限速；登出吊销当前会话 |
| TKT-01 | 学生选择有效房间、类别，填写5～2000字描述，提交后形成唯一编号和创建记录 |
| TKT-02 | 学生仅查看自己的历史，维修人员仅查看当前分配给自己的工单，管理员查看全部 |
| TKT-03 | 管理员选有效维修人员及未来的预约时间派单；重派必须说明原因 |
| TKT-04 | 状态严格遵循设计中的状态机；每次修改必须提交当前版本号 |
| TKT-05 | 维修完成必须填写说明；学生可验收或填写原因要求返修 |
| TKT-06 | 学生仅可取消未派单工单；结束工单不能继续补充内容或上传图片 |
| TKT-07 | 每单最多10张图片，单张5MB，JPEG/PNG/WebP，限2000万像素，授权访问 |
| TKT-08 | 完成后学生评价1～5星，每单一次；列表分页，每页不超过100条 |
| ADM-01 | 管理员查看账号，停用或启用非管理员账号；停用立即阻断会话访问 |
| ADM-02 | 管理员新增楼栋、房间，并可查看最近100条操作审计 |
| STAT-01 | 统计总量、未完成量、完成量、平均完工小时数和评分分布 |
| STAT-02 | 按楼栋、类别、创建时间范围组合筛选；CSV导出与列表权限一致，保留状态筛选 |
| STAT-03 | WebSocket每3秒通知当前账号可见的汇总；总览图表重新读取当前过滤条件并刷新 |
| AI-01 | 支持水路、电路照明、门窗、家具、其他五类本地文本推理 |
| AI-02 | 独立令牌认证；结果包含工单关联、类别、分数、AI来源、时间及模型版本 |
| AI-03 | 阈值及轮询周期可配置；低分结果不入库；网络错误指数退避，最多60秒 |
| AI-04 | 推理失败不阻断报修，管理员可人工分类；重复推理结果按工单去重 |
| AI-05 | 模型不接收图片/视频，日志不打印报修描述；文本本身仍是业务数据，由权限保护 |

## 非功能要求

- 安全：SQL参数绑定；后端强制RBAC与数据范围；Cookie HttpOnly/SameSite；写请求校验头及Origin；CSV公式转义；附件重新编码且不使用上传文件名。
- 一致性：状态更新采用版本条件更新，冲突返回409；事件记录与状态变更同事务。
- 可维护性：Controller/Service/Repository分离，AI独立进程，OpenAPI约定接口。
- 可用性：浏览器无构建运行；移动端可操作；无数据时展示空状态；提交中按钮禁用；AI失效提供人工路径。
- 性能目标：本地50条记录、100次列表请求的P95低于1秒作为课程演示目标，实际结果另行测量，不代表生产容量承诺。

## 核心用例

UC-01 学生报修：前置登录且房间存在，提交描述与类别；后置状态待受理并记录创建事件。图片失败不撤销已创建工单，界面提示可进入详情补传。

UC-02 管理员派单：确认分类后指定维修人员及预约时间；若版本过期返回409，重新获取详情后再提交。

UC-03 维修与返修：维修人员开始并提交处理说明，学生确认或说明问题仍存在；返修回到处理中。

UC-04 统计导出：管理员选择筛选范围并导出UTF-8 BOM CSV；记录导出审计。

UC-05 独立推理：worker领取无预测的活跃工单，调用独立分类服务，将有效分数结果提交后端；低分或异常保持人工处理路径。
